
# SkillSight — Synthetic Dataset Documentation

## 1. Overview

SkillSight uses a fully synthetic workforce dataset
for skill-gap analysis, career recommendations,
workforce risk prediction, and market forecasting.

The dataset is generated using JavaScript,
Mongoose, and @faker-js/faker.

No real employee or confidential HR data is used.

Dataset generation is owned by P3.

## 2. Technology

- Node.js
- MongoDB Atlas
- Mongoose 8
- @faker-js/faker
- Mulberry32 pseudorandom generator
- Fixed random seed: 42

The synthetic dataset is reproducible.
Repeated runs generate equivalent logical records,
although MongoDB ObjectIds may change.

## 4. Database Collections

### User

Stores authentication accounts:
- Email
- Hashed password
- Role: hr or employee
- Linked employeeId where applicable

One HR account and five employee demo accounts
are created.

### Employee

Stores:
- Unique employee code
- Synthetic employee name
- Department
- Job role reference
- Skills and proficiency levels
- Career role interests

Skill proficiency ranges from 1 to 5.

### Skill

Stores:
- Unique skill code and name
- Category
- Description
- Aliases
- Prerequisites
- Market pattern
- Related skills
- Optional embedding

marketPattern is hidden from ordinary queries
and serves as synthetic evaluation ground truth.

Embeddings and related-skill similarities are
generated by P4's AI build.

### Role

Stores:
- Job title
- Department
- Level
- Required skills
- Future skills
- Next career roles

Skill importance weights range from 1 to 3.

### Course

Stores:
- Course title and provider
- Course or certification type
- Target skills
- Entry level
- Duration in hours

### Project

Stores:
- Project code and name
- Department
- Project status
- Start date
- Required skill staffing
- Employee memberships

Statuses:
- completed
- active
- planned

### LearningRecord

Stores:
- Employee reference
- Course reference
- Enrollment status
- Start date
- Completion date where applicable

Statuses:
- enrolled
- completed
- dropped

### MarketDemand

Stores:
- Skill reference
- Month
- Synthetic demand value
- Data source

Each skill has exactly 24 monthly observations.

### Forecast

Stores:
- Historical demand
- Predicted demand
- Forecast trend
- Growth percentage
- Error metrics
- Linear regression parameters

Initially empty until P4 runs the forecast build.

### Review

Stores:
- AI recommendation snapshot
- Review type
- Review status
- HR comments and modifications
- Creator and decision information

Initially empty.

## 9. Special Test Employees

Three employees are intentionally generated
for boundary-case evaluation.

### EMP901 — No Skills

Role: Frontend Developer

Skills: Empty list.

Purpose:
- Verify skill-gap detection
- Verify zero-readiness handling
- Test learning recommendations

### EMP902 — Fully Skilled

Role: Frontend Developer

Skills:
Meets every current role requirement at or above
the required level.

Purpose:
- Verify zero current skill gaps
- Verify high current-role readiness
- Check recommendation relevance

EMP902 can still have future skill gaps.

### EMP903 — Vue Developer Missing React

Role: Frontend Developer

Skills:
- Vue.js: level 4
- JavaScript: level 4
- HTML/CSS: level 3

React is intentionally absent.

Purpose:
- Evaluate semantic skill similarity
- Verify Vue.js is not treated as identical to React
- Test gap detection and learning recommendations

These three special employee invariants are checked
after seeding.

## 12. Learning Records

Each employee receives two learning records.

Small seed:
30 employees x 2 = 60 records.

Full seed:
300 employees x 2 = 600 records.

Statuses include completed, enrolled and dropped.

Completed records contain completion dates.

The three special test employees retain their
intended skill profiles.

Learning completion rate is calculated using:

completed records / total learning records.

## 13. Market Demand History

Each of the 40 skills has 24 months of
synthetic demand observations.

History period:
October 2024 through September 2026.

Total:
40 x 24 = 960 MarketDemand records.

All records have source = "synthetic".

Four market patterns are used:

- Emerging: rapid demand growth
- Growing: gradual demand growth
- Stable: approximately constant demand
- Declining: downward demand movement

Bounded random noise is added to the patterns.

Demand values cannot be negative.

## 14. Forecasting

P4 uses historical demand values to generate
12-month linear regression forecasts.

Forecast period:
October 2026 through September 2027.

Forecasts include:
- Monthly predictions
- Prediction intervals
- Growth percentage
- Trend labels
- MAE and MAPE
- Naive baseline metrics

The hidden marketPattern is not used for
forecast inference.

It is reserved for evaluation.

## 15. Reproducibility

The random generator uses Mulberry32 with seed 42.

Faker also uses seed 42 for synthetic names.

Calling resetRandom() restarts the random sequence.

Repeated seeding regenerates logically consistent
data and the same collection counts.

MongoDB-generated ObjectIds may differ between runs.

## 16. Running the Dataset Generator

From the server directory:

Small dataset:

npm run seed:small

Full dataset:

npm run seed

The commands connect to the MongoDB database
configured in server/.env.

WARNING:
Seeding deletes and recreates the ten application
collections, including users, forecasts and reviews.

Run only against a dedicated development database.

Seeding is prohibited when NODE_ENV=production.

Never run seeding against real employee data.

## 19. Known Limitations

This dataset is synthetic and is not representative
of any real company's workforce.

Market demand patterns are simulated rather
than sourced from live job postings.

Employee roles and skill assignments are generated
using simplified rules.

Proficiency levels are illustrative and are not
measured from real employee assessments.

Forecasting accuracy on synthetic data does not
establish real-world prediction accuracy.

AI recommendations are decision-support outputs,
not automatic HR decisions.

Human review remains part of the workflow.
