
# SkillSight — AI Model Evaluation Report

## 1. Overview

This report documents the measured performance of
SkillSight's AI and forecasting algorithms.

Evaluation was executed using:

npm run eval

The evaluation uses synthetic employee, skill,
course, role, and market-demand data.

All metrics reported below were generated by
the evaluation script.

These findings do not establish real-world
labor-market or hiring prediction accuracy.

## 2. Evaluation Dataset

The AI build processed:

- 40 technical skills
- 12 job roles
- 60 learning courses
- 40 skill-demand forecasts

The evaluation includes:

- 40 forecast records
- 30 predefined skill-matching cases
- 8 predefined learning recommendation cases
- 8 explainability and functional checks

The market-demand history is synthetic.

## 3. Demand Forecasting Evaluation

Model: Linear Regression

Implementation:
server/src/ai/forecast.js

The model fits the latest 12 training months
and forecasts future skill demand.

For backtesting:

- Use a 24-month historical window.
- Reserve the final 6 months for testing.
- Fit regression on the last 12 months
  of the preceding 18 months.
- Compare predictions against held-out actuals.
- Compare against a naive baseline that
  repeats the last training observation.

### Measured Results

| Metric | Result |
|---|---:|
| Forecasts generated | 40 |
| Average model MAPE | 2.205% |
| Average naive MAPE | 5.325% |
| Forecasts beating naive baseline | 75% |
| Historical trend label agreement | 92.5% |

The regression model achieved lower average MAPE
than the naive baseline in this evaluation.

75% of backtested skills achieved lower MAE
than the naive baseline.

Historical trend agreement compares classifications
with synthetic market-pattern labels.

MAPE excludes observations with zero actual
demand. MAE includes these observations.

The reported forecast intervals use a heuristic
residual-spread approximation and are not
calibrated statistical prediction intervals.

## 4. Skill Matching Evaluation

Model: Xenova/all-MiniLM-L6-v2

Implementation:
server/src/ai/skillMatch.js

The matching system uses:

1. Exact skill-name matching
2. Alias matching
3. Semantic embeddings and cosine similarity

Semantic match threshold: 0.60

A predefined set of 30 test phrases was evaluated
against the same expected labels.

Two approaches were compared:

Baseline:
Exact skill names and stored aliases only.

Hybrid:
Exact matching, aliases, and semantic embeddings.

### Measured Results

| Metric | Result |
|---|---:|
| Evaluation phrases | 30 |
| Alias baseline accuracy | 66.7% |
| Hybrid top-1 accuracy | 73.3% |

The hybrid approach improved top-1 accuracy
by approximately 6.6 percentage points using
the displayed rounded results.

The 30 examples include exact names, aliases,
and descriptive technical-skill phrases.

This is a small, predefined evaluation set.
It does not establish accuracy on arbitrary
real-world resumes or job descriptions.

## 5. Learning Recommendation Evaluation

Implementation:
server/src/ai/learning.js

The recommendation system ranks courses using:

- 40% skill-gap coverage
- 25% forecast skill demand
- 20% historical completion rate
- 15% semantic relevance

Eight predefined employee-role evaluation
cases were used.

Model recommendations were compared with
a popularity-based course-ranking baseline.

Both approaches used the eligible course
pool for each case.

### Precision@5

Precision@5 measures the proportion of five
recommendation slots containing courses
that teach at least one predefined relevant skill.

The denominator remains 5 even if fewer
than five courses are recommended.

### Measured Results

| Metric | Result |
|---|---:|
| Evaluation cases | 8 |
| AI recommendation Precision@5 | 72.5% |
| Popularity baseline Precision@5 | 57.5% |

The AI recommender achieved a 15-percentage-point
improvement over the popularity baseline on
these predefined synthetic evaluation cases.

The gold labels are illustrative skill targets,
not independently verified employee outcomes.

## 6. Explainability Evaluation

Implementation:
server/src/ai/explain.js

The explainability helper produces factor
contributions using:

contribution = normalizedValue * weight

The implementation rounds displayed
contributions to three decimal places.

### Measured Results

| Metric | Result |
|---|---:|
| Checks passed | 8 |
| Total checks | 8 |
| Pass rate | 100% |

The executed checks include:

- Mobility explanation consistency
- Learning explanation consistency
- Zero-vector cosine handling
- Negative cosine handling
- Invalid employee ID validation
- Seeded exact skill matching
- Valid readiness score ranges
- Current role excluded as a career transition

These checks verify selected implementation
properties, not overall model correctness.

## 7. Additional Edge Cases

The following scenarios were not measured
in isolated fixtures by this evaluation run:

- Missing model-generated data
- Zero historical market-demand fixture
- Employee with no skill gaps
- Unreachable distinct career target

These should be tested separately before
claiming complete edge-case coverage.

## 8. Evaluation Limitations

### Synthetic market data

The market history is generated rather than
collected from real-world hiring sources.

Low forecast errors may reflect the synthetic
patterns used to construct the dataset.

### Small evaluation sets

Skill matching uses 30 phrases.

Learning evaluation uses 8 predefined cases.

Results may differ on larger or more
representative datasets.

### Pretrained embeddings

MiniLM is used for inference only.

The embedding model was not fine-tuned
on this project's employee data.

Semantic similarity may confuse related
technologies that are not interchangeable.

### Recommendation evaluation

The gold labels were predefined illustrative
skill targets rather than independently
annotated hiring or learning outcomes.

Precision@5 does not establish whether
recommended courses improve employee performance.

### Human oversight

SkillSight provides recommendations,
not final employment decisions.

HR retains responsibility for reviewing
career mobility and learning suggestions.

## 9. Reproducing the Evaluation

Prerequisites:

1. Configure server/.env with MongoDB access.
2. Ensure the synthetic dataset is seeded.
3. Generate embeddings and forecasts.
4. Run the evaluation.

Commands:

cd server

npm run ai:build

npm run eval

Measured results are saved to:

server/eval-results.json

The file is generated locally and should
not be committed to Git.

The evaluation API reads the saved results
when available:

GET /api/market/evaluation

If evaluation has not run, it returns null.

## 10. Conclusion

SkillSight successfully executed evaluation
of its forecasting, semantic matching,
learning recommendation, and explainability
components.

Key measured findings:

- 2.205% average forecast MAPE
- 75% of forecasts beat the naive baseline
- 73.3% hybrid skill-matching accuracy
- 72.5% learning Precision@5
- 8 of 8 explainability checks passed

These results demonstrate the implemented
algorithms on the synthetic hackathon dataset.

Real-world deployment would require
representative datasets, broader validation,
monitoring, and human oversight.
